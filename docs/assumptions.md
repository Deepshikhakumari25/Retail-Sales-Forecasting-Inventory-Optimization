# Assumptions and limitations

- **Synthetic generator:** fixed seed 42, 3 stores, 8 products, 730 daily records per store/product. It models weekly patterns, mild trend, annual variation, random promotions, intermittent zero-demand products, variable store/product scales and periodic simulated replenishment. It is not a real market dataset.
- **Stockouts:** simulated observed sales are capped by simulated available stock and flagged. Demand on a stockout day can be censored; the pipeline reports stockouts and does not impute lost sales.
- **Missing data:** missing promo flag defaults to 0 (no promotion). Required values and malformed dates are errors. No missing-price imputation is performed. Zero quantity is retained.
- **Missing dates:** the quality report counts absent daily rows between each store-product series' first and last observed dates. It does not assume stores should have observations outside that span or infer closures.
- **Features:** calendar values are known for future dates. Lag and rolling values only include earlier observations; future recursive features use prior model forecasts. Future promotions are assumed absent/default 0.
- **Evaluation:** chronological training, validation and test windows, 56 days each by default. Validation MAE chooses a model; the final later test window is not used for selection. Each window uses rolling one-step predictions where earlier actual observations are available. This is not a multi-origin robustness study. MAE and RMSE are reported; panel MASE scales each observation by its own store-product seasonal-naive training error and omits series whose scale is zero.
- **Models:** Seasonal Naive repeats the last observed weekly pattern (or mean for shorter history). Random Forest is trained on lag features and future forecasts are recursive. SBA is an intermittent-demand benchmark with alpha 0.1 and bias correction `(1 - alpha/2)`. No model is assumed superior.
- **Inventory:** recent 90-day observed demand estimates mean and standard deviation. Safety stock uses `z × daily standard deviation × sqrt(lead time)`, assuming independent daily errors and fixed lead time. The default cycle service level is 95%.
- **Order sizing:** inventory position includes on-hand + incoming − backorders (the default simulation has no incoming/backorder fields, so those are zero). At/below reorder point, order quantity raises inventory position to expected demand over lead time + 28-day review period + safety stock. It is rounded up to whole units. EOQ is separate information and does not force the recommendation.
- **Costs:** synthetic unit, ordering and holding-rate inputs are illustrative and have no specified currency. Estimated order value is not actual spend or savings.
- **Deployment:** the dashboard is local and educational. It is not a production service and does not include authentication, live POS integration or automated purchase-order transmission.
